# Развёртывание ОСВ / БДР на сервере

Архив содержит приложение, текущий снимок PostgreSQL и загруженные Excel-файлы.
Снимок сделан 05.11.2026: 8 загрузок (включая две обновлённые выгрузки 26_ОСВ
от 03.11.2026), 8 735 строк ОСВ, 5 221 рассчитанная строка мэппинга,
627 записей мэппинга, файлы около 356 КБ.

С момента предыдущего архива (28.10) в приложении: пакетная загрузка ОСВ
со статусами и историей, новый дашборд с блоком ФОТ, мэппинг с вкладками
«Основной» / «Для ФОТ» (аналитика ФОТ — на дашборде), единый список без
пагинации, импорт через диалог, защита несохранённых правок.

## Что нужно на сервере

- Linux (Ubuntu 22.04/24.04 или аналог).
- Docker Engine 24+ и Docker Compose v2 (`docker compose`, не `docker-compose`).
- Свободный порт `8010` (меняется в `.env`).
- Доступ к Docker Hub для сборки образа и загрузки `postgres:16-alpine`.

### Ресурсы

| Вариант | CPU | RAM | Диск |
|---|---:|---:|---:|
| Минимум для внутреннего контура, 1–20 пользователей | 1 vCPU | 2 ГБ + swap 2 ГБ | 20 ГБ SSD |
| Рекомендуется | 2 vCPU | 4 ГБ | 40 ГБ SSD |
| Если рядом будет nginx, Keycloak, Vault-агент, SIEM/Kaspersky-агент | 4 vCPU | 8 ГБ | 60–80 ГБ SSD |

Сейчас приложение — один процесс FastAPI + PostgreSQL. Сильно нагруженным оно не будет:
основная нагрузка — загрузка Excel и расчёт мэппинга. 2 vCPU / 4 ГБ — спокойный запас.

## Установка

Передать архив на сервер:

```bash
scp osv-bdr-deploy-2026-11-05.tar.gz user@server:/opt/
```

На сервере:

```bash
cd /opt
tar -xzf osv-bdr-deploy-2026-11-05.tar.gz
cd osv-bdr-deploy
bash deploy.sh
```

`deploy.sh`:
- создаст `.env` из `.env.example`;
- сгенерирует случайный пароль PostgreSQL;
- соберёт контейнеры;
- поднимет базу и приложение;
- покажет адрес проверки.

## HTTP → HTTPS (порты 80 и 443)

Развёртывание включает nginx:

- порт **80** — только редирект `301` на `https://…`;
- порт **443** — TLS и проксирование в приложение (`client_max_body_size 30m`,
  чтобы проходила загрузка Excel до 25 МБ);
- прямое обращение к приложению (`APP_PORT`, по умолчанию 8010) слушается
  только на `127.0.0.1` сервера — снаружи сайт доступен исключительно через 443.

При первом запуске `deploy.sh` создаёт самоподписанный сертификат
(`deploy/certs/`, имя из `TLS_CN`). Браузер будет предупреждать о нём.
Корпоративный сертификат: положите `fullchain.pem` и `privkey.pem`
в `deploy/certs/` и перезапустите `bash deploy.sh`.

Порты 80/443 заняты чем-то другим — измените `HTTP_PORT`/`HTTPS_PORT` в `.env`.

Проверить:

```bash
curl -I  http://127.0.0.1/healthz     # HTTP/1.1 301, Location: https://…
curl -k https://127.0.0.1/healthz     # {"status":"ok"}
```

Проверить:

```bash
curl http://127.0.0.1:8010/healthz
docker compose -f docker-compose.deploy.yml ps
docker compose -f docker-compose.deploy.yml logs -f web
```

Открыть в браузере:

```text
http://<IP-сервера>:8010
```

Первый запуск может занять 20–40 секунд: PostgreSQL применяет `deploy/db.sql`,
затем приложение пересчитывает `mapped_rows`.

### Если Docker не может создать сеть

Если при запуске появляется `all predefined address pools have been fully subnetted`,
добавьте в `docker-compose.deploy.yml` явную сеть со свободной подсетью:

```yaml
networks:
  default:
    ipam:
      config:
        - subnet: 10.250.250.0/24
```

Подсеть согласуйте с сетевой командой/ОАИТС, чтобы не пересечься с корпоративной сетью.

## Если порт занят

Изменить в `.env`:

```dotenv
APP_PORT=8011
```

и перезапустить:

```bash
docker compose -f docker-compose.deploy.yml up -d
```

## Важно по безопасности

Текущая версия приложения **без авторизации и без TLS**. Это внутренний контур.
Не публикуйте порт `8010` в интернет.

Правильный вариант для СБ:
- поставить перед приложением корпоративный nginx с TLS;
- закрыть доступ через SSO + MFA/2FA (Keycloak);
- ограничить доступ по IP/VPN;
- подключить журналы к SIEM;
- хранить секреты в Vault MultiCorp;
- использовать Kaspersky для хоста и проверки загружаемых файлов.

Если nginx стоит на том же сервере, привяжите порт к localhost:

```yaml
ports:
  - "127.0.0.1:${APP_PORT:-8010}:8000"
```

и проксируйте на `http://127.0.0.1:8010`.

## Обновление

```bash
cd /opt/osv-bdr-deploy
docker compose -f docker-compose.deploy.yml up -d --build
```

## Остановка

```bash
docker compose -f docker-compose.deploy.yml down
```

Не используйте `down -v`, если не хотите удалить базу: ключ `-v` удаляет volume `pgdata`.

## Резервная копия

```bash
cd /opt/osv-bdr-deploy
bash backup.sh
```

Скрипт создаёт:
- `backups/db_<дата>.sql` — дамп PostgreSQL;
- `backups/uploads_<дата>.tar.gz` — загруженные Excel-файлы.

Восстановление дампа в работающую базу:

```bash
docker compose -f docker-compose.deploy.yml exec -T db \
  psql -U osv -d osv < backups/db_20261028_120000.sql
```

Восстановление файлов:

```bash
tar -xzf backups/uploads_20261028_120000.tar.gz -C deploy/uploads
```

## Если нужен чистый старт без текущих данных

До первого запуска удалите:

```bash
rm deploy/db.sql
rm -f deploy/uploads/*.xlsx
```

Тогда база создастся пустой, а приложение заполнит справочник счетов.
Если `pgdata` уже создан, `db.sql` повторно не применяется — для чистого старта
нужен новый volume (`down -v`), но это удалит текущую базу.

## Пароль PostgreSQL

Пароль задаётся один раз при создании `pgdata`. Если поменять `POSTGRES_PASSWORD`
в `.env` после первого запуска, приложение перестанет подключаться к базе.
Менять пароль нужно и в PostgreSQL, и в `.env`, либо пересоздавать базу.
