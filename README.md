# ОСВ — оборотно-сальдовые ведомости

Веб-приложение для загрузки ОСВ из Excel (1С), хранения строк и итогов в PostgreSQL,
просмотра данных по счетам и подготовки базы для БДР через мэппинг статей,
номенклатурных групп и ФОТ по подразделениям. Сейчас загружены все шесть счетов:
25, 26, 90.01, 90.02, 91.01, 91.02.

## Запуск

```bash
docker compose up -d --build
```

Сайт: **http://localhost:8010**

Порт 8010 задан в `.env`, потому что 8000 на этой машине уже занят другим
контейнером. Пароль PostgreSQL и порт можно изменить в `.env`
(шаблон — `.env.example`).

Остановить:

```bash
docker compose down          # данные сохраняются в volumes
docker compose down -v       # удалить также базу и загруженные файлы
```

## Возможности

- Загрузка `.xlsx` / `.xlsm` пачкой: автоопределение счёта и периода, таблица
  результатов по каждому файлу (загружено / дубликат / отклонено) и история загрузок.
- Разбор иерархии ОСВ: счёт → подразделения → группы → статьи затрат →
  помесячная расшифровка («Обороты за …»).
- Два режима исходной таблицы на странице счёта:
  - **Группировка** — дерево с раскрытием узлов;
  - **Плоская** — листовые записи с отдельными колонками.
- **Мэппинг для БДР**: после загрузки автоматически рассчитывается
  плоская таблица с мэппингом; неразмеченные строки подсвечиваются.
- На странице счёта есть переключатель «Только неразмеченные».
- Вкладка **«Мэппинг»** — две таблицы: единая для всех счетов
  (`Счёт · Год · Признак ОСВ · Подразделение / статья / прочее · Признак БДР`)
  и общая таблица ФОТ для 26 и 90.02 (`Счёт · Год · Подразделение / признак ОСВ · Признак БДР`).
  Цель редактируется кликом прямо в ячейке; есть фильтры, автоприменение и пагинация.
- Вкладка **«ФОТ»** — аналитическая сводка: суммы, категории и структура
  по 90.02 / 26 / 25. Редактирование ФОТ — в отдельных таблицах мэппинга.
- **Импорт мэппинга из Excel** одним листом «Единый мэппинг»
  (`Счёт · Год · Признак ОСВ · значение · Признак БДР`), пустой шаблон
  и выгрузка текущего мэппинга.
- Вкладка **«БДР»** — структура БДР с фактом 3 квартала 2026, расчётными
  строками, ФОТ и справочными строками по 25/26 счетам.
- Вкладка **«Общая»** — единая таблица по всем счетам с фильтрами
  по каждой колонке и пагинацией.
- История загрузок: скачивание исходника и удаление загрузки вместе со строками.
- Защита от повторного импорта одного и того же файла (SHA-256 + счёт).
- JSON API для интеграций.

## Поддерживаемые счета

`25`, `26`, `90.01`, `90.02`, `91.01`, `91.02`.

Счёт берётся из заголовка отчёта («… по счету 25 …») или, если его нет,
из имени файла (`25_ОСВ.xlsx`). Период — из строки «за 3 квартал 2026 г.».
Файлы других счетов отклоняются с понятной ошибкой.

## Как парсится файл

1. Находится заголовок отчёта и счёт.
2. Ищется шапка с группами колонок «Сальдо на начало», «Обороты за период»,
   «Сальдо на конец» и подколонками «Дебет/Кредит».
3. Строки читаются по отступам Excel (`alignment.indent`, fallback —
   `outlineLevel`), поэтому иерархия сохраняется.
4. Строка, повторяющая итог счёта, помечается как «Итого».
5. Заглушки 1С `<...>` заменяются на «Без названия».

Все суммы хранятся как `NUMERIC(20,2)`; в интерфейсе форматируются
по-русски (пробел — тысячи, запятая — копейки).

## Правила мэппинга

Мэппинг применяется к листовым строкам (статья/месяц) после загрузки.
Ключи сравниваются без учёта регистра, `ё/е`, кавычек и лишних пробелов.

| Счёт | Условие | Источник мэппинга |
|---|---|---|
| 90.01 | номенклатурная группа | G–J; для «Сдача имущества в аренду» и «Реализация товаров несобственного производства» задайте «Прочее» в мэппинге |
| 90.02 | статья = Оплата труда / Оплата больничного / Страховые взносы / Взносы в ФСС от НС и ПЗ | M–Q по подразделению |
| 90.02 | остальные статьи | G–J по номенклатурной группе |
| 26 | четыре статьи по оплате труда | M–Q по подразделению |
| 26 | остальные статьи | константа «Общехозяйственные расходы» |
| 25 | четыре статьи по оплате труда | M–Q по подразделению |
| 25 | остальные статьи | константа «Общепроизводственные расходы» |
| 91.01, 91.02 | статья затрат | B–D |

Подразделения участвуют только в разметке ФОТ. В интерфейсе показываются
только те подразделения, которые реально встречаются в строках ФОТ текущих
загрузок; остальные записи M–Q остаются в базе, но не засоряют экран.

Неразмеченные строки сохраняются со статусом `unmapped`, подсвечиваются
в таблицах и группируются на вкладке «Мэппинг» по ключу. После изменения
мэппинга все `mapped_rows` пересчитываются.

Мэппинг хранится по типу, счёту, году и значению: `article` (B–D),
`nomenclature` (G–J), `department` (M–Q, только ФОТ). Счёт входит в ключ, поэтому
одна и та же статья в 91.01 и 91.02 может иметь разные цели. Для G–J
и M–Q берётся последний год в файле (сейчас 2026); B–D без года.

### Импорт и шаблон

На вкладке «Мэппинг» есть две кнопки:

- **«Пустой шаблон»** — `.xlsx` с одним листом **«Единый мэппинг»**:
  `Счёт` | `Год` | `Признак ОСВ` | `Подразделение / статья / прочее` | `Признак БДР`;
- **«Текущий мэппинг»** — та же структура с текущими записями из базы;
- **«Шаблон ФОТ»** — лист `Счёт · Год · Подразделение / признак ОСВ · Признак БДР`;
- **«Текущий ФОТ»** — 74 используемых подразделения 26 и 90.02.

`Признак ОСВ` принимает `Статья`, `Номенклатурная группа` или `Подразделение`.
Файл ФОТ использует отдельный лист и принимается тем же импортом.
Для статей год не используется, для номенклатурных групп и подразделений
указывается год. Подразделения принимаются только для 26 и 90.02;
25-й счёт в мэппинге не участвует. Старые форматы B–D / G–J / M–Q
по-прежнему поддерживаются при импорте для совместимости.

Заполненные строки добавляются или обновляются, пустые пропускаются,
`mapped_rows` пересчитываются автоматически. Повторы схлопываются
по ключу (тип + счёт + год + значение); если для одного ключа встречаются
разные цели, импорт сообщает число конфликтов и использует последнее
значение. Для 90.01 и 90.02 группы «Сдача имущества в аренду» и
«Реализация товаров несобственного производства» автоматически получают
цель «Прочее».

### Редактирование в таблицах

На вкладке `/mapping` два режима: «Основной» — единая таблица для всех
счетов одним списком (без пагинации), и «Для ФОТ» — только таблица ФОТ
для 26 и 90.02. Аналитика ФОТ (карточки сумм, категории, подразделения)
находится на дашборде в сворачиваемом блоке «ФОТ». Неразмеченные строки
показываются сверху. Цель редактируется кликом прямо в ячейке; сохранение — одна
кнопка в шапке таблицы (активна только при наличии правок, показывает
их количество). Пустые ячейки не сохраняются. Несохранённые правки
подсвечиваются, хранятся в черновике и предупреждают при уходе.

Импорт — кнопка «Импорт» справа сверху: в диалоге выбор файла,
«Пустой шаблон» и «Текущий мэппинг» (в режиме ФОТ — шаблон и текущий
ФОТ). Фильтры единой таблицы: счёт, признак ОСВ, статус и поиск;
селекты применяются сразу, поиск — с задержкой, «Сбросить» возвращает
полный список. В режиме «Для ФОТ» фильтр по подразделению, категории
и статусу работает и для таблицы, и для списков подразделений.

### Как заполнить мэппинг быстро

1. Заполняйте цель прямо в ячейке таблицы: клик по ячейке, ввод значения,
   затем «Сохранить». Неразмеченные строки подняты наверх.
2. Данные уже есть в БДР — скачать шаблон, вставить диапазоны B–D / G–J / M–Q
   и импортировать файл.
3. ФОТ удобнее заполнять в общей таблице ФОТ для 26 и 90.02 на вкладке «Мэппинг»:
   она показывает только подразделения ФОТ и сохраняется отдельно.

## БДР

Вкладка `/bdr` строится на лету из последних загруженных ОСВ и их мэппинга.

- **Выручка** — 90.01 по целям ГП / ПИР / СМР / ЗУ / Прочее / Аутстаффинг.
- **Себестоимость** — 90.02 без статей ФОТ, по тем же укрупнённым целям.
- **ФОТ** — статьи оплаты труда из 90.02 и 26 (25 счёт исключён);
  категория ФОТ влияет только на аналитику, не на итог.
- **Общехозяйственные расходы** — 26 без ФОТ.
- **Общепроизводственные расходы** — 25 без ФОТ, показаны справочно
  и не входят в итоги.
- **Финансовая деятельность и прочие** — цели 91.01/91.02:
  % к получению, % к уплате, % за ЗУ, прочие доходы/расходы.
- Валовая прибыль = выручка − себестоимость; прибыль от продаж =
  валовая прибыль − ФОТ − общехозяйственные; прибыль до НО БУ =
  прибыль от продаж + финансовый результат + прочие доходы − прочие расходы.

Факт доступен за 3 квартал 2026 (июль–сентябрь), поэтому в таблицу
добавлена колонка «3 квартал 2026». Колонки 2025, плановые 2026–2028
и налог пока пусты — в системе нет источника этих данных. Детализация
СМР (Форт Сталин, ТХ, монтаж, …) пуста, потому что мэппинг укрупнённый.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты используют `tests/fixtures/25_ОСВ.xlsx`: проверяют счёт, период, 158 строк,
итоги, равенство суммы помесячных строк итогу, структуру дерева, правила
мэппинга и разбор импортируемого Excel. Всего 30 тестов.

## База данных

- `accounts` — справочник счетов;
- `uploads` — загрузки (файл, хеш, период, итоги);
- `osv_rows` — строки ОСВ с `parent_id` (дерево), уровнем, типом узла и суммами;
- `mapping_entries` — мэппинг: тип ключа (`article` / `nomenclature` /
  `department`), значение и целевка; поле `payload` — резерв под будущий
  импорт файла БДР;
- `mapped_rows` — рассчитанные листовые строки для БДР: счёт, подразделение,
  номенклатурная группа, статья, месяц, Дт/Кт, целевой мэппинг и статус.
  Пересчитывается при загрузке, изменении мэппинга и старте приложения.

## Ограничения

- Старый формат `.xls` не поддерживается — пересохраните в `.xlsx`.
- Авторизации нет: приложение рассчитано на локальный запуск.
- Повторная загрузка того же файла не создаёт дубль; для перезагрузки
  удалите старую запись на странице счёта.
- Импорт мэппинга ожидает колонки B–D / G–J / M–Q; при другой структуре
  файла потребуется доработка.
- В БДР пока нет факта 2025 и планов 2026–2028, налога на прибыль
  и детализации СМР: нет исходных данных/целей такого уровня.
- 25 счёт не участвует в итогах — показан справочно.
